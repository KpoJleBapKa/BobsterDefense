# Технічне завдання

## Заміна TNT-моделі балістичної ракети на літаючий Trident

### 1. Мета

У плагіні **Bobster** замінити поточну візуальну модель балістичної ракети, яка реалізована через літаючий `TNT`, на сутність **Trident**.

Основна причина зміни — зробити політ ракети візуально більш схожим на справжню ракету без використання кастомного resource pack.

При цьому вся існуюча логіка балістичної ракети повинна зберегтися:

* запуск по заданих координатах;
* балістична траєкторія;
* дальність;
* потужність;
* вибух у точці призначення;
* можливість перехоплення ППО;
* повідомлення про запуск/тривогу;
* ідентифікація ракети як об'єкта Bobster.

---

# 2. Нова модель ракети

Замість `TNTPrimed` для ракети використовується:

```java
Trident
```

Trident використовується **лише як візуальне представлення ракети**.

Вибухова механіка Trident не використовується.

Ракета повинна мати власну логіку:

```text
BallisticMissile
    ↓
Trident entity
    ↓
Custom flight controller
    ↓
Impact
    ↓
Bobster explosion logic
```

---

# 3. Spawn ракети

При запуску балістичної ракети створюється `Trident`.

Приклад логіки:

```java
Trident trident = world.spawn(startLocation, Trident.class);
```

Для Trident потрібно встановити:

```java
trident.setPickupStatus(AbstractArrow.PickupStatus.DISALLOWED);
trident.setPersistent(false);
trident.setCritical(false);
```

Гравець не повинен мати можливість підібрати ракету.

Після завершення польоту Trident обов'язково видаляється:

```java
trident.remove();
```

---

# 4. Ідентифікація ракети

Необхідно мати можливість відрізнити ракетний Trident від звичайного тризубця гравця.

Для цього використати `PersistentDataContainer`.

Наприклад:

```java
bobster:ballistic_missile
```

Значення:

```java
1
```

Додатково бажано зберігати:

```text
bobster:missile_id
bobster:missile_owner
bobster:missile_power
bobster:missile_target_x
bobster:missile_target_z
```

Наприклад:

```java
trident.getPersistentDataContainer().set(
    BALLISTIC_KEY,
    PersistentDataType.BYTE,
    (byte) 1
);
```

---

# 5. Фізика польоту

Не покладатися повністю на стандартну фізику Trident.

Рух ракети контролюється Bobster.

Рекомендується створити окремий клас:

```java
BallisticMissile
```

Приблизна структура:

```java
class BallisticMissile {

    UUID missileId;

    UUID entityUuid;

    UUID ownerUuid;

    Location start;

    Location target;

    double speed;

    double maxHeight;

    int power;

    MissileState state;
}
```

---

# 6. Фази польоту

Політ розділити на три основні фази.

```text
LAUNCH
   ↓
ASCENT
   ↓
BALLISTIC
   ↓
DESCENT
   ↓
IMPACT
```

Enum:

```java
enum MissileState {
    LAUNCH,
    ASCENT,
    BALLISTIC,
    DESCENT,
    IMPACT,
    DESTROYED
}
```

---

# 7. Старт ракети

На початку ракета повинна рухатися переважно вгору.

Наприклад:

```text
Y ↑

       🔱
       |
       |
       |
       🔥
       🔥

Launcher
```

Стартова швидкість:

```text
X/Z — мала
Y — велика
```

Наприклад:

```java
Vector velocity = new Vector(
    direction.getX() * 0.3,
    1.5,
    direction.getZ() * 0.3
);
```

Конкретні значення повинні бути винесені в конфіг.

---

# 8. Розгін

У перші секунди ракета повинна поступово набирати горизонтальну швидкість.

Приклад:

```text
Tick 0

     🔱
     ↑


Tick 20

        🔱
       ↗


Tick 40

              🔱
             ↗
```

Необхідно уникнути різкого переходу з вертикального польоту у горизонтальний.

---

# 9. Балістична дуга

Основна траєкторія повинна нагадувати дугу.

```text

                       🔱
                    ↗      ↘
                 ↗            ↘
              ↗                  ↘
           ↗                        ↘
        ↗                              ↘
     🚀                                  💥

 launcher                              target
```

Максимальна висота повинна залежати від дальності.

Наприклад:

```java
maxHeight =
    minHeight +
    distance * heightMultiplier;
```

З обмеженням:

```text
minimum height
maximum height
```

Наприклад:

```yaml
ballistic:
  min-height: 60
  max-height: 220
  height-per-block: 0.18
```

---

# 10. Пікірування

При наближенні до цілі ракета повинна перейти у виражене пікірування.

```text
             🔱
              \
               \
                \
                 🔱
                  \
                   \
                    💥
```

Остання фаза повинна бути швидшою за початковий набір висоти.

Це створюватиме відчуття падіння боєголовки.

---

# 11. Орієнтація Trident

Trident повинен завжди бути направлений у напрямку руху.

Орієнтація розраховується на основі:

```java
Vector velocity
```

При кожному оновленні траєкторії потрібно синхронізувати напрямок Trident з напрямком ракети.

Візуально не повинно бути ситуації:

```text
рух →→→

🔱
↑
```

Тризубець повинен дивитися приблизно:

```text
──────🔱→
```

---

# 12. Реактивне полум'я

За Trident повинен постійно генеруватися реактивний слід.

Основні частинки:

```java
Particle.FLAME
```

Додатково:

```java
Particle.SMOKE
```

або доступний у поточній версії Minecraft аналог димових частинок.

---

# 13. Позиція полум'я

Полум'я повинно з'являтися **позаду ракети**, а не просто в поточній координаті Trident.

Розрахунок:

```java
Vector backwards =
    velocity.clone()
            .normalize()
            .multiply(-1);
```

Позиція:

```java
Location flameLocation =
    trident.getLocation()
           .add(backwards.multiply(offset));
```

Умовно:

```text
🔥🔥🔥🔥  🔱 ──────>
```

а не:

```text
🔥
 🔥
  🔱
```

---

# 14. Склад реактивного сліду

На кожному тіку або кожні 2 тики створювати:

```text
FLAME
FLAME
SMOKE
```

Приклад:

```java
world.spawnParticle(
    Particle.FLAME,
    flameLocation,
    4,
    0.05,
    0.05,
    0.05,
    0.01
);
```

і:

```java
world.spawnParticle(
    Particle.SMOKE,
    flameLocation,
    2,
    0.08,
    0.08,
    0.08,
    0.01
);
```

---

# 15. Довший слід

Для кращого ефекту можна створювати частинки у декількох точках позаду ракети.

Наприклад:

```text
🔥 🔥 🔥 🔥 🔱
```

Координати:

```java
loc1 = missilePos - direction * 0.5;
loc2 = missilePos - direction * 1.0;
loc3 = missilePos - direction * 1.5;
```

Інтенсивність повинна зменшуватися з відстанню від ракети.

---

# 16. Режими двигуна

Під час активного розгону:

```text
FLAME + SMOKE
```

Під час середньої балістичної фази можна трохи зменшити кількість частинок.

Під час фінального пікірування:

```text
FLAME + SMOKE
```

знову збільшити.

Приклад:

```text
ASCENT
🔥🔥🔥🔥🔥 🔱

BALLISTIC
🔥🔥 🔱

DESCENT
🔥🔥🔥🔥 🔱
```

---

# 17. Звук ракети

Додати звук працюючого двигуна.

Звук не потрібно запускати кожного тіку.

Наприклад кожні:

```text
6–10 ticks
```

відтворювати відповідний Minecraft sound.

Гучність повинна залежати від відстані до ракети.

Необхідно уникнути надмірного спаму звуками.

---

# 18. Вибух

Trident сам по собі не відповідає за вибух.

При досягненні точки удару:

```java
detonateMissile(missile);
```

Порядок:

```text
1. визначити координату удару;
2. видалити Trident;
3. створити explosion effects;
4. застосувати поточну Bobster-логіку вибуху;
5. видалити BallisticMissile з активного списку.
```

---

# 19. Виявлення зіткнення

Не покладатися лише на `ProjectileHitEvent`.

Під час кожного оновлення перевіряти:

```text
відстань до target
```

і:

```text
collision з блоками
```

Удар вважається таким, що відбувся, якщо:

```java
distanceToTarget <= impactRadius
```

Наприклад:

```yaml
impact-radius: 2.5
```

---

# 20. Потужність

Поточна система потужності ракети повинна залишитися без змін.

Наприклад:

```text
Power 1
Power 2
Power 3
Power 4
Power 5
```

Trident не впливає на силу вибуху.

Він лише показує положення ракети.

---

# 21. Взаємодія з ППО

ППО повинно працювати не з будь-якими Trident, а лише з:

```text
bobster:ballistic_missile = 1
```

ППО отримує координати активної ракети через `BallisticMissileManager`.

Наприклад:

```java
List<BallisticMissile> missiles =
    missileManager.getActiveMissiles();
```

---

# 22. Перехоплення

При попаданні ракети ППО в Trident балістична ракета переходить:

```text
ACTIVE
↓
DESTROYED
```

Далі:

```text
Trident remove
↓
air explosion effect
↓
particles
↓
sound
↓
remove missile
```

Основний бойовий вибух балістичної ракети при цьому **не відбувається**.

---

# 23. Повітряний підрив

При перехопленні створити менший вибух.

Наприклад:

```text
FLASH
EXPLOSION particles
SMOKE
FIREWORK-like effect
```

При цьому за замовчуванням не руйнувати блоки.

---

# 24. Chunk loading

Поточний механізм chunk-loading ракети потрібно зберегти.

Ракета не повинна:

```text
зникнути;
зависнути;
телепортуватися;
перестати оновлюватися;
```

при переході між чанками.

Bobster повинен забезпечувати завантаження чанків уздовж траєкторії ракети.

---

# 25. Видалення ракет

Ракета повинна автоматично видалятися, якщо:

```text
досягнута ціль;
ракета перехоплена;
світ став недоступним;
entity була видалена;
минув максимальний час життя;
сервер/plugin вимикається.
```

---

# 26. Максимальний час життя

Додати параметр:

```yaml
max-flight-time-seconds: 120
```

Якщо ракета існує довше:

```text
120 секунд
```

вона аварійно видаляється.

Це запобігає появі "загублених" Trident.

---

# 27. Заборона pickup

Ракетний Trident ніколи не повинен випадати як предмет.

Навіть після:

```text
collision;
server lag;
chunk reload;
player interaction.
```

Встановити:

```java
PickupStatus.DISALLOWED
```

і додатково перехоплювати потрібні події, якщо це необхідно.

---

# 28. Заборона Loyalty

У ракетного Trident не повинна працювати механіка:

```text
Loyalty
```

Він не повинен повертатися до власника.

Trident не повинен отримувати стандартні enchantments.

---

# 29. Візуальні ефекти під час старту

У точці запуску створити:

```text
велике полум'я;
дим;
звук запуску.
```

Перші приблизно:

```text
10–20 ticks
```

кількість частинок може бути збільшена.

Візуально:

```text
            🔱
            ↑
           🔥
          🔥🔥
         ☁️🔥☁️
       launcher
```

---

# 30. Конфігурація

Додати секцію:

```yaml
ballistic-missile:

  entity:
    type: TRIDENT

  flight:
    launch-speed: 1.4
    cruise-speed: 2.2
    descent-speed: 2.8

    min-height: 60
    max-height: 220

    max-flight-time-seconds: 120

  exhaust:
    enabled: true

    flame:
      enabled: true
      count: 4

    smoke:
      enabled: true
      count: 2

    trail-length: 1.5

  impact:
    detection-radius: 2.5

  interception:
    explosion-power: 1.5
    break-blocks: false
```

Значення надалі можна буде підібрати тестуванням.

# 31. Архітектура

Рекомендована структура:

```text
missile/
 ├─ BallisticMissile.java
 ├─ BallisticMissileManager.java
 ├─ BallisticMissileController.java
 ├─ BallisticTrajectory.java
 ├─ MissileState.java
 ├─ MissileEffects.java
 └─ MissileExplosion.java
```

---

# 32. BallisticMissileManager

Відповідає за:

```text
створення ракети;
реєстрацію;
пошук;
видалення;
список активних ракет.
```

Приклад:

```java
Map<UUID, BallisticMissile> activeMissiles;
```

---

# 33. BallisticMissileController

Відповідає за оновлення ракети кожного тіку:

```java
updatePosition();
updateVelocity();
updateRotation();
spawnExhaust();
checkCollision();
checkTarget();
checkLifetime();
```

---

# 34. BallisticTrajectory

Відповідає виключно за математичну траєкторію:

```java
Vector calculateVelocity(
    BallisticMissile missile,
    double progress
);
```

Це дозволить надалі міняти фізику ракети без переписування інших систем.

---

# 35. MissileEffects

Відповідає за:

```text
полум'я;
дим;
звуки;
launch effect;
flight effect;
interception effect;
impact effect.
```

---

# 36. Tick task

Не створювати окремий `BukkitRunnable` для кожної ракети.

Використати один глобальний tick-loop:

```java
for (BallisticMissile missile : activeMissiles) {
    missileController.tick(missile);
}
```

Це буде значно простіше контролювати при великій кількості ракет.

---

# 37. Частота оновлення

Фізику бажано оновлювати:

```text
кожен tick
```

тобто:

```text
20 разів/сек
```

Particle effects за необхідності можна генерувати:

```text
кожні 1–2 ticks
```

для зменшення навантаження.

---

# 38. Сумісність зі старою системою

Після зміни:

```text
TNT entity
```

повинна повністю зникнути з реалізації польоту балістичної ракети.

Але логіку:

```text
launch command
coordinates
power
cooldown
permissions
warnings
air defence
explosion
```

потрібно максимально залишити без змін.

Фактично міняється шар:

```text
Missile visual/flight entity
```

з:

```text
TNT
```

на:

```text
Trident
```

---

# 39. Очікуваний результат

Після запуску гравець повинен бачити приблизно таку картину:

```text
START

                🔱
                ↑
               🔥
              🔥🔥
             ☁️🔥☁️


ASCENT

                🔱
              ↗
         🔥🔥🔥


BALLISTIC

🔥🔥 🔱 ─────────────>


DESCENT

                         🔱
                           ↘
                            🔥
                             🔥
                              ↘
                               💥
```

При цьому:

* немає літаючого TNT;
* гравець бачить Trident як корпус ракети;
* позаду постійно працює реактивний двигун;
* ракета рухається по плавній балістичній траєкторії;
* Trident правильно повернутий по напрямку руху;
* при попаданні ракета вибухає за правилами Bobster;
* ППО може перехопити її в повітрі;
* перехоплений Trident не падає на землю і не стає предметом.

---

# 40. Критерії готовності

Функціонал вважається завершеним, якщо виконуються всі умови:

* [ ] TNT більше не використовується як модель ракети.
* [ ] При запуску створюється Trident.
* [ ] Trident неможливо підібрати.
* [ ] Trident не повертається до власника.
* [ ] Trident ідентифікується як ракета Bobster.
* [ ] Ракета має плавну балістичну траєкторію.
* [ ] Trident орієнтований у напрямку польоту.
* [ ] За ракетою видно полум'я.
* [ ] За ракетою видно димовий слід.
* [ ] Ефекти знаходяться саме позаду ракети.
* [ ] Працює стартовий ефект.
* [ ] Працює існуюча система потужності.
* [ ] Працює вибух у точці удару.
* [ ] Працює система ППО.
* [ ] ППО може знищити Trident-ракету.
* [ ] При перехопленні основний бойовий вибух не відбувається.
* [ ] Ракета нормально проходить між чанками.
* [ ] Після завершення польоту entity гарантовано видаляється.
* [ ] Після рестарту/disable плагіна не залишаються ракетні Trident.
* [ ] Звичайні Trident гравців ніяк не зачіпаються системою Bobster.
